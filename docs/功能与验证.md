这份清单对应原方案功能，不把“能导入模块”算成模型效果验证。`机制测试`验证数学或数据契约，`模型运行`验证真实网络执行，`历史结果`沿用已有实验；完整收益需固定划分消融。

## 本次执行顺序

1. 阅读原方案，核对两份 GitHub 代码与 3090/4090 的实际文件；确认当前选择的室内 appearance20。
2. 将室内版本补入 `yolo_indoor`，保留原功能；建立新仓库，记录上游来源。
3. 保留 Y/E、ViTPose、密度和计数代码；复用已有实现，补齐统计、质量、行为、复核、回流模块。
4. 执行机制测试、真实图像推理、真实视频推理、实际训练器数据加载和 GPU 前后向；修正发现的接口问题。
5. 整理实现与验证记录、学术方法、参数和许可，发布新仓库。历史模型与私有数据发布不覆盖。

## 完整训练与效果实验的边界

本次集成完成的是功能实现和运行验证，未重新训练整个六阶段模型。既有 Y/E 配置中的冻结划分、checkpoint 哈希和选型证据都被保留。新快照若不满足某条训练契约，必须生成符合协议的新实验配置，不能伪造证据或绕过检查。

建议收益实验依次使用：既有基线→加入 20% 插值约束→加入 Q²/Q-MoE→加入漏标鲁棒监督→加入 B-TCA→完整采样闭环。每次固定源视频、区段、测试标注和计算预算，同时报告召回、误检、IDSW、IDF1、最差视频与置信区间。行为 Macro-F1 需要人工行为标注；目前不能计算真实行为识别准确率。
