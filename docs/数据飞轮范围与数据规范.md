# 数据飞轮范围与数据规范

本项目负责数据飞轮：从室内外原始观测生成候选标签，经质量证据、人工复核和划分约束形成可追溯的训练数据。它是团队完整成果中的数据生产与迭代模块，不承担整套作品交付。这个范围由用户明确确认，配置记录于 [flywheel_scope.json](../configs/flywheel_scope.json)。

## 文档条款如何适用

依据用户提供的《作品提交要求.docx》（2026 年 9 月版）和《数据集及评测机制说明20260527.docx》，按工作归属采用要求。文件 SHA-256 保存在范围配置中，原始文档不复制到公开仓库。

| 文档内容 | 对本模块的适用方式 |
|---|---|
| 数据标注采用 COCO 或 YOLO | 提供通用 COCO 导出，保留原训练快照及 YOLO 出口 |
| 提供标注、划分、抽帧脚本和说明，标注包不含图像帧 | 生成独立标注包，由团队后续汇总到 05_数据标注成果 |
| 明确坐标边界、多人多轮复核、漏标重标和忽略区域机制 | 说明真实流程与完成状态；每个转换与复核决定可追溯 |
| 说明外部公开数据的使用 | 配置记录来源、用途、许可及是否进入快照，未核实项明确保留 |
| 个体与群体行为分析（2.2） | 按用户后续要求实现通量、热图、时间网络和群体时序；保留可观测性，候选经确认后才能形成监督 |
| 蜂学与养蜂生产意义（2.3） | 以一手文献和真实上下文解释指标，输出分蜂、天气、暴露等复核线索，不将缺失证据补成诊断 |
| mAP、MOTA、IDF1 与其他性能指标 | 用于下游数据价值实验，不把完整竞赛系统的得分门槛当作飞轮验收门槛 |
| 四 EXE、ONNX、Windows DLL、断网、退出码、推理输出等 | 属于正式推理与整套作品交付，不纳入本模块标准化 |

正式检测推理的 200/600 框上限不适用于数据标注；标注导出不按该上限截断。正式推理帧号的 1-based 规则不用于改写原视频源帧编号。POSE 推理的关键点数量建议和 OKS sigma 不要求本标注集增加并不存在的点或编造标定参数。

## 两类输出分别使用

`export-training` 生成 E 训练器的 schema-v2 数据，包含质量、伪标签和忽略区域监督字段；普通 COCO/YOLO 读取器不能自动执行这些训练语义。

`export-annotations` 生成与训练器解耦的标准标注交付：

```text
data_version/
  annotations/<video>/<group>/confirmed.coco.json
  annotations/<video>/<group>/candidates.coco.json
  splits/train.txt  val.txt  calibration.txt  test.txt  unassigned.txt
  audit/records.jsonl
  frame_manifest.jsonl
  extract_frames.py
  标注说明.md
  resolved_config.json
  manifest.json
  build_status.json
```

这只是数据模块目录。存在内容的确认/候选 COCO 文件才生成，未确认空帧不会变成人工负样本。审计文件保存隐藏插值、拒绝与忽略区域，不将它们强行塞入 COCO 正样本。

COCO 文件按视频及标注群组分开，`image_id`/`annotation_id` 是各文件内的正整数索引，`source_track_id` 才是原始身份。多人同帧数据未仲裁前不可相加。源帧物理位置跨 train/val/calibration/test 时导出拒绝；轨迹/区段/近重复隔离仍由实验划分契约进一步验证。

框采用原图像素坐标，COCO 为 xywh，不添加 `+1`。越界框裁剪并保留原坐标；裁剪后的退化框只留审计。关键点保持 head、abdomen_tip 两点，缺失点固定 `(0,0,0)`；置信度与 COCO 可见性分别记录。如果源第三列本身就是 COCO 可见性，输入声明 `keypoint_encoding: coco_visibility`；否则默认按置信度解释，显式 `keypoint_visibility` 优先。

## 使用

修改 [annotations.example.json](../configs/annotations.example.json) 的输入路径、版本、来源和真实划分。不要把示例值直接当作现有数据的已确认信息。

```bash
bee-flywheel export-annotations --config configs/annotations.example.json --output /data/bee26/flywheel_data/version_001
bee-flywheel validate-annotations --input /data/bee26/flywheel_data/version_001 --output /data/bee26/version_001_check.json
```

源文件已有的域、视频、群组和划分优先保留。新目录禁止覆盖，失败状态也记录下来。校验覆盖文件哈希、COCO 索引/坐标/可见性、物理源帧划分和图像帧未被混入；不把格式通过说成所有框都正确，也不把待划分数据说成已经可以训练。

源视频基准未确认时保留 `frame_index_base: null`。抽帧脚本要求显式提供 0 或 1，不猜测编号。外部数据清单若仍未核实，`external_data_declaration_complete` 保持 false。

## 数据飞轮的验收依据

本模块重点检查：标签状态是否真实、数据能否正确读取、复核决定是否可追溯、训练与校准是否隔离、来源与版本能否复现。覆盖率、复核成本、错误回流率及下游固定协议消融需要真实记录支持。缺少未执行实验时保留“未验证”，而不是套用整套参赛工程的缺项判定。
